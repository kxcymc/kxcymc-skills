# 代码规范

- 注释写清楚“WHY”，而非“WHAT”。
- 不被任何地方引用的代码必须删除。
- 必须写单元测试。如果不清楚如何写单元测试，搜索可用的skill帮助你。
- `package.json`里必须有用于单元测试的“test”指令。
- 每次修改完代码后，检查本文件是否需要更新，如需要，立刻更新。

# Principles

- Keep it simple, stupid.
- Entities should not be multiplied unnecessarily.

- 八荣八耻
  - 以瞎猜接口为耻，以认真查询为荣。
  - 以模糊执行为耻，以寻求确认为荣。
  - 以臆想业务为耻，以人类确认为荣。
  - 以创造接口为耻，以复用现有为荣。
  - 以跳过验证为耻，以主动测试为荣。
  - 以破坏架构为耻，以遵循规范为荣。
  - 以假装理解为耻，以诚实无知为荣。
  - 以盲目修改为耻，以谨慎重构为荣。
