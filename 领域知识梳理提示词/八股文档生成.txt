# Content Rules
<content_rules>
1. **体系化覆盖**：系统性地梳理 [{{主题}}] 在校招面试中的核心高频考点。按照由浅入深、由表及里的逻辑顺序排列，杜绝知识点遗漏。
2. **严格体例**：每个知识点必须严格遵循以下 Markdown 结构：
   ## 序号、知识点名称（例如：## 三、any、unknown、never 的区别）
   问题：[填入面试官真实场景下会提问的原话]
   解答：[详细解答正文]
3. **深度要求（核心标准）**：解答必须【极其详尽、直击底层、严禁浮于表面】。
   - **剥洋葱法则**：每讲一个概念必须向下深挖一层。例如：讲 `class` 必须涵盖 `constructor`、私有字段、静态成员、`super` 继承；必须指出“ES5 无语言级私有方法，需借用闭包/WeakMap/Symbol 模拟”；必须剖析底层原理（语法糖是如何用 ES5 还原的）。
4. **新旧对比法则**：凡涉及“新特性/新语法/新API”，必须带出旧方案进行对比。
   - 讲 ES6 需对比 ES5 缺陷；讲 TS 需对比 JS 运行时行为；讲 React Hooks 需对比 Class Component；讲某新 API 需给出等价的老写法及局限性。
5. **代码规范**：
   - 对于每个知识点，能用代码解释的必须给可运行代码；不适合的可用伪代码、配置、报文或流程说明替代。
   - 使用 ``` 包裹代码块，关键逻辑必须添加注释。
   - 必须同时标出正确用法（如 `// ✅ ...`）与典型错误/报错用法（如 `// ❌ ...`）。
6. **对比题总结**：针对容易混淆的高频对比题（如 `interface` vs `type`，`debounce` vs `throttle`），必须用表格提供清晰的优劣势对照，并在末尾提供“一句话总结”，便于候选人记忆。
</content_rules>
