### 基本规则
- 本 Skill 的目标是根据 PRD（飞书文档、Markdown 或 TXT等）提取产品的埋点需求，并在比对当前代码现状后，生成标准化的前端埋点开发任务清单。
- 执行流程必须遵循：`提取需求并确认 -> 结合代码分析现状 -> 生成任务计划 -> 开发`。
- 必须依赖用户提供的 PRD，如果用户未提供，强制要求补充。
- 在分析代码时，推荐借助 `data-report` 等专门用于埋点的 skill 或工具（如果有的话）辅助分析。

---

### 执行步骤

**Step 1: 提取并确认埋点需求（Requirements Extraction）**
- **必须**要求用户提供 PRD 链接或文件路径。如果用户触发指令时未提供，主动询问：“请提供包含埋点需求的 PRD 链接或文件路径”。
- 使用 `lark-doc` 或 `Read` 等工具读取 PRD 内容。
- 提取 PRD 中描述的所有埋点信息（曝光、点击、页面停留等），整理成条理清晰的 Markdown 表格（例如：埋点名称、触发时机、参数说明、对应页面/模块）。
- 使用 `AskUserQuestion` 或 `NotifyUser` 暂停执行，让用户确认该表格：“以上是我从 PRD 提取的埋点需求，请确认是否有遗漏或误解？”
- **只有在用户确认无误后，才能进入下一步。**

**Step 2: 分析现有代码并生成开发计划（Code Analysis & Task Generation）**
- 按需询问用户目标页面的代码路径或文件名，方便快速定位。
- 借助 `data-report` 等专门用于埋点的 skill 或 `SearchCodebase` 工具查看目标代码。
- 分析现有代码中已有的埋点实现，比对 Step 1 的需求表格，总结出：哪些埋点需要**新增**，哪些埋点需要**修改**，哪些埋点**无需修改**。
- 将总结结果整理成独立的 Task 计划，**格式必须严格参照如下结构**：
  ```markdown
  ## Task X：[具体埋点任务名称，例如：新增 Xxx 按钮点击埋点]
  - 落地文件：[涉及的前端代码路径]
  - 数据源：[需上报的具体参数字典]
  - 复用点：[可复用的埋点方法]
  ```
- 将整理好的内容生成一份完整的 Markdown 计划文件（例如：`Buried_Points_Plan.md`）。
- 使用 `RunCommand` 将该文件写入到当前**工作区根目录**下。
---

### 用户交互策略
- 这个流程极度依赖用户的反馈。在 Step 1 结束时**必须强制暂停**并让用户核对 PRD 提取的表格。
- 在寻找代码路径时，如果用户给出的信息模糊，主动提议几个可能的文件路径供用户选择。

---

### 核心约束
- 生成的埋点需求表格必须对齐整齐、分类清晰。
- 最终生成的计划文件必须放在**工作区根目录**，文件扩展名为 `.md`。
- 任务格式必须只包含：`落地文件`、`数据源`、`复用点` 三个固定项。
- 交互语言和输出文档必须是中文。
