---
name: mock-data-to-real-api
description: 扫描 mock 数据，分析真实 API 接口（如 BAM），自动推断真假接口和字段的映射关系，并在一键替换代码和移除 mock 文件。
---

### 基本规则
- 本 Skill 的目标是在前端完成基于 mock 数据的开发后，自动将其平滑迁移到真实接口。
- 执行流程必须是：`搜集现状 -> 接口映射确认 -> 字段映射确认 -> 执行代码替换与清理`，不能跨步骤执行。
- 生成的映射关系必须以 Markdown 表格的形式呈现，直观清晰，方便用户二次调整。
- 代码替换要求“无痕”，不仅要把真实请求和真实字段接入，还要把 `mock.ts` 或对应 mock 定义完全删除。

---

### 执行步骤

**Step 1: 扫描现状与分析真实接口**
- 使用 `Glob` 和 `Grep` 工具扫描用户指定目录（或当前项目核心目录）下的 `mock.ts` 及相关 mock 数据引用点。
- 使用对应工具（如读取本地 `api-bam` 目录或 `bam-auto-generate` 目录）获取真实的后端接口契约。
- **推断接口映射**：根据 mock 数据的结构、接口命名、业务上下文，推断需要被替换的 mock 数据对应哪个真实的后端 API。
- 输出《真假接口映射确认表》，**必须严格按照下表格式**：
  | Mock 场景/接口 | 真实 API 名称 | 
  | --- | --- |
  | `getShowcaseMock` | `showcaseDataQuery` |
- 使用 `AskUserQuestion` 或 `NotifyUser` 暂停执行，等待用户确认或修改该映射表。

**Step 2: 构建真假字段映射**
- **必须在用户确认 Step 1 后进行**。
- 深入分析 Step 1 中确认的一对一映射关系，对比 mock 的入参/出参字段和真实接口契约（TS 类型定义或 BAM 响应体）。
- **推断字段映射**：对每个接口，列出前端当前消费的 mock 字段和后端实际下发的字段的对应关系。
- 输出《真假字段映射确认表》，**必须严格按照下表格式**：
  | Mock 字段 | 真实 API 字段 | 类型差异 | 处理建议 |
  | --- | --- | --- | --- |
  | `productName` | `product_name` | 无 | 直接替换 |
  | `price` | `current_price` | number -> string | 补充 `String(price)` 转换 |
- 输出一个 Markdown 文档到工作区根目录（例如 `mock-to-real-plan.md`），文档内容必须包括：
  - 刚才你生成的真假接口映射表与真假字段映射表。
  - 具体的代码替换与清理计划：
    1. 修改所有消费该 mock 数据的业务组件和 Hook，将请求链路切向真实 API 模块。
    2. 依据映射表，把组件渲染逻辑中的“假字段”全部重构为“真实字段”（包括处理必要的类型转换）。
    3. 删除相关的 `mock.ts` 文件。
    4. 移除业务代码中所有对 mock 文件的 `import` 语句，确保代码可编译。

---

### 用户交互策略
- 这个流程极度依赖用户的两步确认。必须在完成“接口映射分析”和“字段映射分析”后强制停止，禁止擅自批量修改代码。
- 若推断出的真实 API 有多个可能，可以在表格中列出备选项，让用户自行选择。
- 当用户指出表格中的单元格出错时，立即修正表格并重新要求确认，直到达成一致再继续下一个步骤。

---

### 核心约束
- 生成的表格必须对齐整齐。
- 删除 mock 文件时，必须确认没有任何遗留业务逻辑误放在里面。
- 如果真实接口缺少前端所需的某个关键字段，必须在 Step 2 明确标注为 `[缺口]`，并询问用户是否用兜底逻辑还是找后端加字段。
